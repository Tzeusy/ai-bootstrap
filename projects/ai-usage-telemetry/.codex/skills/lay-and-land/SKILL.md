# AI Usage Telemetry Topology

This skill routes to accepted pre-implementation topology. Reconcile these maps
when implementation evidence exists.

Trigger examples: "where should this component live?", "what may depend on the
ledger?", "which boundary does this data cross?"

| Map | Read when... |
|---|---|
| [Pillar index](../../../about/lay-and-land/README.md) | Orienting to map status and authority |
| [Components](../../../about/lay-and-land/components.md) | Checking ownership, dependency direction, or component boundaries |
| [Data flow](../../../about/lay-and-land/data-flow.md) | Tracing source facts, trust transitions, persistence, or sink delivery |
| [Deployment](../../../about/lay-and-land/deployment.md) | Changing mounts, privileges, network behavior, persistence, packaging, or recovery |
| [Assets index](../../../about/lay-and-land/assets/README.md) | Finding topology diagram sources |

Use `/legends-and-lore` when a placement question becomes a contract question,
and `/spec-and-spine` when it becomes required behavior.
