# V1 Boundary

This document declares the first product boundary for **AI Usage Telemetry**.

**Status:** Draft doctrine, pending explicit human-owner adoption. It does not
authorize implementation or OpenSpec authoring.

[Observed] The project begins from planning and inspected-source evidence; no
implementation exists yet. The items below describe what v1 must deliver, not
what the current repository already provides.

## V1 Ships

- [Inferred] Claude Code and Codex source families using only registered local
  usage sources, with stream-level cursor, quarantine, freshness, and health.
- [Inferred] A self-contained, long-running Docker image that polls on a
  configurable interval with a five-minute default.
- [Inferred] Explicit, resolved read-only leaf source mounts and exactly one
  writable state volume owned by the service. Credential-bearing auth stores,
  broad parent mounts, and symlink-based scope expansion are rejected.
- [Inferred] A local SQLite ledger that retains normalized usage and quota
  records indefinitely, including the source identity needed for idempotent
  accounting.
- [Inferred] Eventually exact accounting for every identifiable, parseable
  event: input/output and supported cache/reasoning token dimensions plus one
  unique usage-request contribution per native usage-bearing event.
- [Inferred] Quota snapshots normalized to canonical `0-1` utilization and
  accompanied by separate source observation time, collection time, and
  explicit fresh, stale, or unknown state.
- [Inferred] Per-stream health and freshness with explicit quarantine state, so
  a broken stream does not stop healthy streams while family/global summaries
  continue to report the degradation.
- [Inferred] A sink-independent local query and health surface through stable,
  read-only SQLite views: `usage_events`, `usage_event_amounts`,
  `quota_snapshots`, `source_health`, `sink_health`, and `ledger_health`. V1
  exposes no inbound API or application port.
- [Inferred] Two independent, optional exports:
  - OTLP Metrics with bounded, low-cardinality measures and allowlisted
    attributes;
  - PostgreSQL with normalized usage and quota tables plus allowlisted metadata
    in JSONB.
- [Inferred] Four separate deny-by-default controls: a code-owned extraction
  registry, stable ledger admission/schema, a PostgreSQL projection allowlist,
  and an OTLP attribute/vocabulary registry. Runtime configuration can narrow
  projections but cannot widen extraction or ledger admission.
- [Inferred] Repository-basename project labels by default and configured account
  aliases where discovering a native identifier would require credentials.
  Export or configuration changes never alter a fact's logical identity or
  accounting fingerprint.

## V1 Defers

[Inferred] V1 postpones the following capabilities or delivery surfaces:

- **OpenCode support.** [Unknown] Its local usage-event shape was observed, but
  no proposed and reviewed credential-free local quota source has been
  established. V1 does
  not ship a partial adapter that quietly omits a product-level capability.
- **Additional tools.** [Unknown] Future local tools may not expose identifiable,
  parseable, credential-free usage and quota events. Each source needs its own
  evidence and contract.
- **Token costs and billing accuracy.** Provider pricing, discounts, plan rules,
  and invoices are outside the usage-fact contract.
- **Dashboards.** Query and visualization experiences may consume the sinks
  later; they are not part of this collector.
- **Native Prometheus Pushgateway output.** OTLP Metrics is the v1 metrics
  boundary; another delivery path must justify its added semantics and support
  burden.
- **Host schedulers.** Cron, systemd timers, and platform-specific launchers are
  unnecessary for a long-running container.

## Constitutional Exclusions

The following are prohibited by the Draft doctrine, not merely postponed. They
require an owner-adopted doctrine amendment before a later RFC may propose
them:

- **Prompt or response auditing.** Content collection is outside the project's
  purpose and trust boundary.
- **Cloud API credential use.** V1 does not mount auth stores or call cloud APIs
  to enrich local facts.
- **Automatic retention controls for normalized local history.** The v1 ledger
  retains accepted records indefinitely. Automatic expiry, pruning, sampling,
  retraction, or aggregate-only replacement requires an owner-adopted doctrine
  amendment. Lossless SQLite maintenance and narrowly owner-authorized privacy
  repair do not weaken that logical-retention contract.

## Platform Targets

- [Inferred] Any local developer environment with a Docker-compatible container
  runtime, explicit bind mounts for supported source logs, and a persistent
  writable volume.
- [Inferred] A multi-architecture container distribution so the runtime
  contract is not tied to one host CPU family. The same locked inputs, ledger
  schema, normalization fixtures, privacy boundary, and local-only behavior must
  pass native smoke tests on `linux/amd64` and `linux/arm64`.
- [Inferred] Python managed with `uv` is the intended implementation platform.
  This doctrine does not fix package layout, library choices, schemas, or image
  construction; those belong in downstream design contracts and specs.
- [Inferred] OTLP Metrics and PostgreSQL are separately optional. Neither is
  required to collect into or query the local ledger.

## Quality Bar

[Inferred] V1 is successful only when all of these are true:

- Replaying the same identifiable source events does not change normalized
  counts, while newly completed events are eventually incorporated exactly
  once.
- Only a registered irrelevant record may advance a stream cursor without a
  fact. Unknown or malformed complete records hold the stream cursor before the
  record and quarantine that stream until the format or data is resolved.
- A restart or optional-sink outage cannot erase committed local history.
- A malformed or changed source format produces a stream-specific quarantine
  state with freshness, while healthy streams continue polling and aggregate
  health remains visibly degraded.
- Prompt and response content values are never decoded, materialized, retained,
  or emitted, including through diagnostics and error paths; syntax traversal
  alone does not create an application value, and credential-bearing stores
  never enter the container.
- Every extracted, admitted, or exported field passes its distinct registry;
  empty or missing projection permission means the field is not exported, and
  configuration alone cannot make a source field safe.
- OTLP output remains bounded in cardinality; PostgreSQL separates normalized
  usage and quota facts from allowlisted JSONB metadata.
- Quota values use the canonical `0-1` scale and cannot be mistaken for fresh
  data when their source snapshot is stale.
- A developer can run the product with the documented read-only sources and
  writable state volume without installing a host scheduler or supplying cloud
  credentials.
- The local-only deployment performs no sink connection or DNS work, and every
  supported architecture exposes the same read-only views and health semantics.
